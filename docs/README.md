# Gate capstone documents

These documents are review drafts until their owners and assigned reviewers accept them. They convert the capstone brief and team design session into decisions that can be implemented and defended.

## Required hand-ins

| Artifact       | Owner                          | Location                                     |
| -------------- | ------------------------------ | -------------------------------------------- |
| Design doc     | Each slice owner               | `docs/slices/`                               |
| ADR            | Each slice owner               | `docs/adr/`                                  |
| Bug report     | Each assigned breaker          | Added during break week                      |
| Peer letter    | Each engineer                  | Submitted privately, not stored in this repo |
| System diagram | Team                           | `docs/team/system-design.md`                 |
| Runbook        | Team                           | `docs/team/runbook.md`                       |
| Post-mortem    | Team, only if something breaks | Added after an actual incident               |

## Review protocol

Read the document before the meeting. Every review must include at least one question and one specific proposal. Nothing merges until its design document has an approving reviewer outside the slice.

Each design document contains an AI disclosure. AI assistance does not transfer authorship: the named owner must revise and be able to defend every decision.
